# The native layer owns design and ADRs own historical rationale

<a id="adr-0010"></a>

- **Decision:** `docs/design/design.typ` is the standing design, `CONTEXT.typ` owns canonical vocabulary, `docs/COVERAGE.md` maps implementation parts, and anchored ADRs retain material decisions and provenance. README and application/testing/supply-chain guidance remain operational entry points.
- **Authorization:** the owner's ecosystem documentation migration explicitly authorizes consolidating obsolete reports, fresh organization and native project setup. It does not authorize runtime/API fixes, commits, publication, live provider calls or new historical claims.
- **Retired duplication:** the package decision register, progress tracker, historical evidence/attack/security matrices, four unpublished migration guides, four probe reports and two handoff reports are replaced by specific ADR/contract destinations. HTTP Gun adoption and conformance README prose becomes concise raw-receipt reproduction guidance.
- **Alternatives:** preserving complete historical reports with banners leaves a competing architecture and status corpus. Copying them into ADRs would preserve the duplication. Immutable revision links retain detailed old tables while concise ADRs preserve conclusions, alternatives and limits.
- **Source preservation:** raw evidence JSON/logs, vendored oracle/license material, manifests, provider/config/schema fixtures, executable harnesses, examples and production source are retained. No package version changes. There is no published release history to discard; the construction diary is condensed to current Unreleased capabilities.
- **Rationale limit:** this record concerns documentation ownership. It neither retrospectively accepts open design choices nor treats formatting/render success as semantic acceptance.
