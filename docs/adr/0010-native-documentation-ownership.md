# Usage is compiled examples, oracle and benchmark references are retained, and the design owns everything else

<a id="adr-0010"></a>

- **Decision:** `docs/design/design.typ` is the standing design, `CONTEXT.typ` owns canonical vocabulary, `docs/COVERAGE.md` maps implementation parts, and anchored ADRs retain material decisions and provenance. `README.md` is the human entry point with a short usage section, `AGENTS.md` carries agent instructions, gate commands and links to the reference documents, and `docs/ORACLE.md` and `docs/BENCHMARKS.md` retain the independent references and the local measurements. Usage is taught by runnable code: one compiled and tested example per topic in `consumer/src/warden_reference/usage/`.
- **Usage as code:** each README usage block is a verbatim region of an example, marked `// docs:begin NAME` and `// docs:end NAME`. `scripts/check-doc-examples.py` runs in `scripts/check` and fails when a block differs from its source or an example region is shown by no block. `consumer/test/usage_test.gleam` runs every example against the local test provider. A change to the public API that breaks an example fails the gate, so the usage cannot drift from the library.
- **Oracle and benchmark documents:** `docs/ORACLE.md` names each reference implementation, its upstream, pinned revision or digest, what the comparison establishes, how outcomes are classified, the exclusions and deliberate differences, how to rerun it and the limits of the claim. `docs/BENCHMARKS.md` holds scope, method, how to run, environment and dated retained results as observations. The two link to each other, to the design's validation gates and to their ADRs, and both are linked from `AGENTS.md` and the README. Raw receipts stay as non-markdown data under `docs/evidence/`.
- **No longer present:** a standalone usage guide, a testing guide, a supply-chain guide, an application-responsibilities guide and a changelog. Their rules live in the design, their runnable parts in the examples, their commands in `AGENTS.md`, and their provenance in `docs/ORACLE.md` and the ADRs.
- **Changelog:** the package has no published release, so a changelog would only restate the design and these ADRs. Release history starts with the first published release.
- **Authorization:** the owner's ecosystem documentation migration authorizes consolidating obsolete reports and the example-and-reference layout above. It does not authorize runtime or API fixes, publication, live provider calls or new historical claims.
- **Alternatives:** prose usage guides drift from the API unless something compiles them, and the earlier uncompiled snippets did. Folding the oracle and benchmark material into the design would bury pins and limits that reviewers need beside the receipts. Preserving the old historical reports with banners leaves a competing architecture and status corpus; immutable revision links retain their detailed tables instead.
- **Source preservation:** the conformance summary, manifests, provider fixtures, executable harnesses and production source are retained. Earlier receipts and logs are in repository history. Oracle inputs are fetched into `build/oracle-inputs/` at run time and checked against a recorded digest; the oidcc record declarations stay committed because path dependents compile the probes that use them (`docs/ORACLE.md`). No package version changes.
- **Rationale limit:** this record concerns documentation ownership. It neither retrospectively accepts open design choices nor treats formatting or render success as semantic acceptance.
