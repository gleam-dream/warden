# Every cache incarnation owns fresh discovery and its fetches

<a id="adr-0007"></a>

- **Decision:** cache processes start empty and discover independently. Fetch results target the actual cache incarnation. A guardian owns the worker and terminates it on cache loss; stale notifications cannot settle newer work. Whole-tree startup joins old owned children before reusing names.
- **History:** `8c750e5` on 2026-10-05 fixed stale fetch completion and child-name restart races. `d97d9c8` on the same date removed manual-start seed snapshots. `0a0907f` and `f3847d1` recorded the final contract and measured allocation costs. Earlier D9/D11 startup-seeding prose is superseded.
- **Failure evidence:** the prior public validator could reject removed key A and then accept it again after stale completion or manual-cache restart. Scheduling barriers reproduced owned-process loss and held old registrations before fixes. The current design captures the delivered behavior rather than preserving old failures as active findings.
- **Alternatives:** routing to stable names confused distinct cache authorities. Replaying the original snapshot improved restart availability but reintroduced removed keys. Name takeover or increasing supervisor restart allowance would mask unfinished cleanup. A shared lifecycle coordinator would couple independent clients unnecessarily.
- **Consequences:** replacement readiness now depends on fresh provider availability/compatibility. Manual start awaits the first attempt; one retained metadata/failure result prevents races with background recovery. Failed start shuts down only its tree within remaining budget and may return while cleanup drains.
- **Resources:** one active fetch adds one guardian, three monitors, one link and one result hop; idle caches add no helper. The extra decoded-key-set copy grows with input. Old-child startup adds at most five transient monitors and may hold that parent's synchronous management callback up to the startup timeout.
- **Measurement limit:** the recorded 5,000-key sample used 828,903 JSON bytes and a 2,160,024-byte decoded term; median extra term delivery was 4.55 ms and the held guardian occupied 2.55 MB after GC. Parsing dominated. These local OTP28/four-scheduler samples are neither peak-memory nor deployment bounds; full original tables remain available in history.
