# A sealed compare-and-set port preserves Warden custody authority

<a id="adr-0004"></a>

- **Decision:** one three-operation Store serves pending login and custody records. Warden owns protocol transitions; adapters supply atomic insert-if-absent, replace-at-version and expiry deletion. Every durable record is sealed and bound to kind, key and version.
- **History:** D19–D21 were recorded on 2026-10-03 in `5a7da27`. D4's in-memory-only ownership was superseded by the public CAS port. Runtime `logins.gleam`, `custody.gleam`, `sealed.gleam` and `port.gleam` now establish the current implementation.
- **Alternatives:** exposing six OAuth-specific adapter operations would transfer state-machine correctness to every application. Trusted plaintext stores would make database readers token holders and writers identity constructors. Stateless encrypted cookies do not provide shared replay authority.
- **Sealing consequences:** AES-256-GCM with fresh 96-bit nonce hides token/reference/claims material. Digest keys hide bearer references; current/previous key rings permit rotation. Whole-row rollback remains outside AEAD and requires protected writers/backups or independent monotonic authority. Rotate before random-nonce usage approaches about 2^32 seals per key.
- **Clock decision:** D20 superseded D14's monotonic persistent lifetimes with wall-clock Unix seconds so records survive nodes/restarts. Hosts must synchronize clocks; clock steps affect expiry. Monotonic milliseconds still bound local operations. Idle writes are coalesced rather than mandatory on every read.
- **Capacity decision:** D14 and ecosystem default decision 5 retained unbounded session count per identity. Evicting old sessions is application product policy; pending login storage retains an explicit default capacity of 100,000.
- **Consumption precision:** the original laboratory and verification contract required atomic expiry rejection with clock sampling inside the store-owned critical section. The current general CAS port owns only version atomicity; Warden samples expiry before the write. That mechanism does not establish the required atomic expiry boundary. The pending ruling must decide how to preserve that requirement and verify a blocked-CAS expiry schedule. This is a source-level contract gap, not a reproduced runtime failure or approval to weaken the requirement.
- **Recovery:** install commands retain their reference/identity/material and idempotent command history; logout tombstones prevent late recovery resurrection within the retained horizon. CAS tests do not prove operational durability or rollback protection.
- **Provenance:** [D14/D19/D20/D21/D24](https://github.com/gleam-dream/warden/blob/f3847d102c0db9f66e4d4a72a9c7b3028507c7ac/docs/decisions.md); `testing.check_store`, store/custody/login tests, and compiled consumer custom adapter. Original prototype contracts are retained in immutable Oversight history.
